# 第 11 课：把升级状态写成可恢复的记录

前置：第 10 课。先确认 EEPROM 型号、页大小和容量，也可先实现文件/RAM 后端来测试记录格式。

## 状态与数据同时设计

至少记录：格式版本、记录序号、当前状态、新旧版本、新旧镜像长度和 CRC、候选/备份槽、记录 CRC。使用固定字节格式，不把 C enum/struct 直接整块写 EEPROM。

参考代码的 0x00 状态、0x01 长度、0x05 旧长度是学习入口；本课采用新格式，不与原二进制记录兼容。

## 双记录实验

选择两个不会跨越错误写入边界的记录区。生成新记录时先写非当前副本，读回验证完整性后才把它视为更新的有效记录。上电分别检查版本/字段范围/CRC，再按序号规则选择有效记录；序号回绕规则需要明确。

EEPROM 写完成要考虑 ACK polling、页边界和供电中断。不能假设一个多字节 I2C 写事务在掉电时原子完成。单独一个状态字节也不足以证明其他字段已落盘。

## 提交顺序

```text
接收全部数据 → flush → 校验读回
  → 记录长度/CRC/版本等元数据
  → 最后提交 DOWNLOADED
```

Boot 只有看到完整有效的 DOWNLOADED 记录和对应有效镜像，才允许进入安装。默认未知状态进入恢复接收，不随意跳转。

## 实验

模拟在每个字节位置停止记录写入，再重启选择记录。损坏其中一份 CRC、两份均损坏、状态无效、长度溢出，结果都应确定。先在模拟后端完成，再用真实 EEPROM 断电验证。

CMake 中 metadata_format 可以独立于 eeprom_backend；前者无需 include MCU 头，后者负责 I2C 硬件。

## 验收

至少一份有效记录时恢复到可解释状态；两份都坏时进入明确恢复模式。解释为什么“状态写完再写长度”存在掉电窗口，为什么状态 NORMAL 不表示 App 的所有字节一定正确。
