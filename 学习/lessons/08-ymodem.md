# 第 08 课：把 Ymodem 作为可独立理解的协议组件

前置：第 05、07 课。参考 09 工程及 29 阶段的 Receive_Packet；协议代码待实现。

## 目标边界

传输层提供读字节/读块/发送/超时；解析层识别帧并验证；文件会话管理包号、长度、重试；存储接收回调负责保存有效载荷。不要把擦除任意地址的 Flash 调用混在每个协议分支。

建议形成 ymodem 静态库，PUBLIC 暴露协议接口，PRIVATE 隐藏解析细节，通过回调接入串口和存储。协议算法不直接 include stm32f4xx.h。

## 解析顺序

识别 SOH/STX → 确定 128/1024 载荷长度 → 收完整包头/载荷/CRC → 校验序号反码 → CRC16/XMODEM → 检查会话序号 → 交付一次。

首包有文件名和 ASCII 长度；数据包最后一包按剩余真实长度截取；处理 EOT、取消、超时和重传。序号按 uint8 回绕；重复的上一包可 ACK，但不能重复写入。

## 离线实验先于硬件

构造几段固定字节输入：正确首包、CRC 错误、包号反码错误、重复包、提前结束、超长文件名、无终止符的长度串。解析失败不能调用存储 write 回调。

实际串口可慢速发送并故意暂停，验证超时恢复。再用 Ymodem 上位机传一个小文件，在 RAM/外部存储读回比对。

本课不把“存在 Cal_CRC16 函数”当作检查完成，要沿接收调用链确认它实际参与判断。不同课程阶段可能只有包号/长度检查。

## 验收

保存一次首包、数据包和结束握手记录。解释 ACK 的时机：缓冲区已可靠接管还是已经持久写入？若缓冲区仍被下一包复用，为什么不能过早 ACK？
